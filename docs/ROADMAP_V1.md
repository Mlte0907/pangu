# 盘古大版本迭代方案：从「记忆仓库」到「认知伙伴」

> **版本**：v0.4.1 → v1.0 愿景  
> **日期**：2026-09-27  
> **定位**：本文是**大版本迭代方案**，与 `ROADMAP.md`（小版本日常维护）互补。  
> **依据**：基于代码中已存在但未接线的高级模块（`multi_agent.py` / `world_model.py` / `causal_reasoning.py` / `narrative.py` / `deep_emotion.py` / `collaborative_intelligence.py`），以及用户反复强调的方向——「让盘古自己来」「更强大」。

---

## 一、核心洞察：盘古当前是什么，应该成为什么

| 维度 | 当前（v0.4.1） | 目标（v1.0） |
| --- | --- | --- |
| **本质** | 被动记忆仓库：用户问，它答 | 主动认知伙伴：它预判、它提醒、它协作 |
| **架构** | 单进程 + 17 个自主任务 | 多智能体网络 + 共享记忆 |
| **推理** | 检索 + 关键词匹配 | 因果推理 + 预测 + 叙事理解 |
| **交互** | 用户驱动 | 盘古主动（基于世界模型预测用户需求） |
| **边界** | 单用户私有 | 跨平台集体智慧（隐私保护下共享知识） |

**一句话**：从「你问我答」到「我懂你所需」。

---

## 二、六大突破方向

### 突破 1：多智能体协作网络（Multi-Agent Collective）

**现状证据**：`pangu/memory/multi_agent.py` 已通过 lazy import 接入 `handlers/advanced.py`（5 处），是多智能体工具的底层实现。当前是**单点工具调用**，未形成协作网络。

**愿景**：盘古不是一组平坦的记忆，而是一个**专家团队**。

```
┌─────────────────────────────────────────────────┐
│  协调者（Coordinator）                           │
│  理解意图 → 分派给专家 → 综合结果               │
├──────────┬──────────┬──────────┬────────────────┤
│ 代码专家 │ 运维专家 │ 决策专家 │ 创意专家       │
│ 管代码记忆│ 管踩坑 │ 管决策树 │ 管发散联想     │
│ 修 bug   │ 管监控 │ 管优先级 │ 管类比推理     │
└──────────┴──────────┴──────────┴────────────────┘
         │
         ▼
    共享记忆层（当前 Drawer 结构）
```

**核心能力**：
- **辩论**：同一问题让不同专家独立推理，再辩论出最优解（`debate.py` 已有基础）
- **分派**：协调者根据问题类型自动选专家
- **综合**：多专家结果融合，不是简单投票

**验收标准**：
- 给定一个复杂问题（如「这个 bug 为什么修不完」），系统自动调度 ≥ 2 个专家并行推理
- 辩论后的答案质量 > 单一专家（用 `enhanced_evaluation.py` 打分）
- 响应时间 < 5s

---

### 突破 2：世界模型驱动的预测与主动干预

**现状证据**：`pangu/memory/world_model.py` 已通过 lazy import 接入 `handlers/advanced.py`（4 处），是世界模型工具的底层实现。当前是**静态场景匹配**，未形成预测闭环。

**愿景**：盘古不只记住「发生了什么」，而是建模「为什么会这样」，并**预测下一步**。

**核心能力**：
- **因果链**：`A → B → C` 的因果链建模（`causal_reasoning.py` 已有基础）
- **预测**：基于历史模式预测「你现在打算做什么」
- **主动提醒**：不等用户问，盘古主动说「根据过去经验，这个操作可能会失败，因为...」

**场景举例**：
```
用户：我要把 Python 3.11 升级到 3.13
盘古（主动）：⚠️ 上次你升级 Python 版本时，
  onnxruntime 编译失败了 3 次，最后回滚了。
  这次建议先在虚拟环境里验证 onnxruntime 兼容性。
  相关记忆：[2026-06 部署优化] [2026-09 CI 矩阵修复]
```

**验收标准**：
- 用户开始一个操作前，盘古能主动推送 ≤ 3 条相关历史经验
- 预测准确率 > 60%（用历史数据回测）
- 误报率 < 20%

---

### 突破 3：因果推理引擎（从「相关」到「因果」）

**现状证据**：`pangu/memory/causal_reasoning.py` 已通过 lazy import 接入 `handlers/timeline.py`（5 处），是时间线因果分析的底层实现。当前是**事后归因**，未形成主动预测。

**愿景**：当前搜索告诉你「这两件事一起出现」，因果推理告诉你「**这件事导致那件事**」。

**核心能力**：
- **因果图**：从记忆中提取因果链，构建因果图
- **反事实推理**：「如果当时没做 X，会发生什么？」
- **根因分析**：不只是「surface symptom」，而是追到根因

**验收标准**：
- 给定一个失败场景，能输出 ≥ 2 层因果链
- 因果链的每个环节都有记忆证据支撑
- 与 `knowledge_graph.py` 打通，因果图和知识图谱叠加

---

### 突破 4：叙事记忆（从「列表」到「故事」）

**现状证据**：`pangu/memory/narrative.py` 已通过 lazy import 接入 `handlers/llm_tools.py`（3 处），是叙事生成工具的底层实现。当前是**用户触发**，未形成自动编织。

**愿景**：人类记忆的本质不是列表，是**故事**。盘古应该把零散记忆编织成连贯叙事。

**核心能力**：
- **时间线叙事**：把分散在 100 条记忆里的片段编织成完整故事
- **多视角叙事**：同一事件的不同侧面（技术视角 / 决策视角 / 情感视角）
- **故事演化**：新记忆进来时，自动更新相关故事，而不是新增一条孤立记录

**场景举例**：
```
用户：我们是怎么从 v0.3 升级到 v0.4 的？
盘古（叙事）：
  「这次升级始于 2026-09-19，当时你发现 AGENTS.md 太长了...
   中间经历了三次返工，第一次是因为...
   最终在 09-27 完成，核心教训是...」
  —— 涉及 23 条记忆，按时间线编织，标注因果关系
```

**验收标准**：
- 给定一个主题，能输出 ≥ 3 段的连贯叙事
- 叙事中的每个事实都能追溯到具体记忆
- 叙事随新记忆自动更新（增量更新，不是全量重算）

---

### 突破 5：跨平台集体智慧（隐私保护下的知识共享）

**现状证据**：`pangu/memory/collaborative_intelligence.py` 已通过 lazy import 接入 `handlers/advanced.py`（4 处），是集体智慧工具的底层实现。用户 2026-09-18 已定「公开策略」：系统/技术/修复类记忆写入公共区。当前是**单平台检索**，未形成跨平台共享。

**愿景**：盘古不只服务一个用户，而是**多平台 agent 的知识网络**。

**核心能力**：
- **跨平台检索**：搜索时可选「只搜私有」或「包含公共知识」
- **知识众包**：多用户对同一问题贡献经验，盘古交叉验证后提炼共识
- **差分隐私**：共享知识时自动脱敏（`differential_privacy.py` 已有基础）

**验收标准**：
- 搜索公共知识时，结果标注来源平台
- 众包知识的准确率 > 单一来源（交叉验证）
- 私有记忆绝不出现在公共搜索结果中（红线）

---

### 突破 6：情感与个性化（从「通用」到「懂你」）

**现状证据**：`pangu/memory/deep_emotion.py` 已通过 lazy import 接入 `handlers/llm_tools.py`（3 处），是情感分析工具的底层实现。当前是**被动分析**，未影响搜索排序。

**愿景**：盘古应该理解用户的**情绪状态**和**认知偏好**，个性化服务。

**核心能力**：
- **情绪感知**：从用户的输入方式（简短/详细、急躁/平和）推断情绪状态
- **个性化排序**：搜索结果按用户偏好排序（代码人员看代码片段，管理者看决策摘要）
- **认知风格适配**：有人喜欢先看结论，有人喜欢先看证据——盘古自动适配

**验收标准**：
- 情绪状态识别准确率 > 70%
- 个性化排序的用户满意度 > 通用排序（A/B 测试）
- 认知风格适配不需要用户手动配置

## 三、实施路径（三阶段）

### 阶段一：接线骨架（4 周）

**目标**：把已存在的 6 个高级模块接线到主流程。

| 模块 | 接线方式 | 验收 |
| --- | --- | --- |
| `multi_agent.py` | 搜索入口加「多专家辩论模式」 | 辩论结果 > 单模型 |
| `world_model.py` | 搜索后加「预测」区块 | 能输出 ≤ 3 条预测 |
| `causal_reasoning.py` | 知识图谱加因果边 | 能输出因果链 |
| `narrative.py` | 时间线视图加叙事模式 | 能输出连贯故事 |
| `collaborative_intelligence.py` | 搜索加「公共知识」选项 | 能搜到跨平台知识 |
| `deep_emotion.py` | 输入预处理加情绪标签 | 能识别情绪状态 |

### 阶段二：深度融合（6 周）

**目标**：模块之间打通，形成闭环。

- 多智能体辩论的结果写入记忆 → 世界模型更新 → 预测更准
- 因果推理的结果 → 知识图谱 → 叙事记忆
- 情绪标签 → 个性化排序 → 搜索结果

### 阶段三：产品化（4 周）

**目标**：用户可感知的体验提升。

- 盘古 dashboard 加「预测」区块
- 搜索加「叙事模式」开关
- 多智能体辩论结果可视化

## 四、风险与对策

| 风险 | 对策 |
| --- | --- |
| 多智能体延迟过高（多模型串行调用） | 并行调用 + 超时降级到单模型 |
| 预测误报率高 | 严格阈值 + 用户反馈闭环 |
| 因果推理的因果链没有充分证据 | 标注置信度，低置信度不展示 |
| 集体智慧隐私泄露 | 差分隐私 + 严格脱敏 + 红线测试 |
| 情绪识别不准 | 只作为辅助信号，不影响核心功能 |
