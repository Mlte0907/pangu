# 盘古记忆系统架构优化方案

> 版本：v2.1 | 日期：2026-09-19 | 状态：提案

## 1. 背景与问题

### 1.1 当前架构

盘古目前采用**多房间 + 钥匙**的认证体系，原本是为企业级多用户场景设计：

```
当前架构（多用户设计）：
┌─────────────────────────────────────────────────────────┐
│                      盘古记忆系统                         │
├─────────────────────────────────────────────────────────┤
│  房间A (DSH)  │  房间B (MCP)  │  房间C (API)  │  公共区   │
│  ───────────  │  ───────────  │  ───────────  │  ───────  │
│  记忆隔离     │  记忆隔离     │  记忆隔离     │  共享记忆  │
│  钥匙A        │  钥匙B        │  钥匙C        │           │
└─────────────────────────────────────────────────────────┘
```

### 1.2 问题分析

| 问题 | 描述 | 影响 |
|------|------|------|
| **过度设计** | 房间隔离是为多用户设计，但实际只有你一人使用 | 复杂度高，维护成本大 |
| **记忆孤岛** | 不同房间的记忆互相隔离，无法跨平台共享 | 在 DSH 遇到的问题，MCP 无法复用 |
| **钥匙管理** | 每个平台需要单独的钥匙，管理繁琐 | 接入新平台成本高 |
| **知识断层** | 平台切换时，已有经验无法自动迁移 | 重复踩坑，效率低下 |

### 1.3 核心洞察

> **盘古是个人级记忆系统，不是企业级多用户系统。**
> 
> 不管记忆如何隔离，所有记忆都是你一个人在不同平台操作的产物。
> 隔离只会阻碍知识的流动和复用。

## 2. 优化目标

### 2.1 设计原则

1. **统一记忆** - 所有平台的记忆共享，不再隔离
2. **简化认证** - 移除房间/钥匙，改用简单的 Token 审核
3. **知识生成** - 盘古自动从记忆中提取知识，形成知识库
4. **平台感知** - 记录记忆来源平台，方便追溯
5. **记忆进化** - 写入时自动匹配相关记忆，更优记忆自动替换旧记忆，旧版本保留为快照
5. **记忆进化** - 写入时自动匹配相关记忆，更优记忆自动替换旧记忆，旧版本保留为快照
5. **记忆进化** - 写入时自动匹配相关记忆，更优记忆自动替换旧记忆，旧版本保留为快照

### 2.2 预期收益

| 方面 | 当前 | 优化后 | 提升 |
|------|------|--------|------|
| 复杂度 | 高（房间+钥匙） | 低（Token审核） | -70% |
| 记忆共享 | 隔离 | 统一 | +100% |
| 知识复用 | 无 | 自动生成 | +∞ |
| 用户体验 | 需管理多个钥匙 | 简单接入 | +80% |

    """

    - 所有平台的记忆都可以被搜索到

    results = hybrid_search(query)

### 3.4 记忆进化机制

#### 3.4.1 核心理念

> **记忆不是静态的，而是不断进化的。**
> 
> 每次写入记忆时，盘古会自动匹配相关记忆。
> 如果新记忆比旧记忆更优（更准确、更完整、更新），则自动替换旧记忆。
> 旧版本保留为快照，方便复查。

#### 3.4.3 评估标准

```python
def evaluate_memory_quality(memory: dict) -> float:
    """
    评估记忆质量
    返回 0-1 分数，越高越好
    """
    score = 0.0
    
    # 1. 内容完整性（0-0.3）
    content_length = len(memory.get("content", ""))
    if content_length > 500:
        score += 0.3
    elif content_length > 200:
        score += 0.2
    elif content_length > 50:
        score += 0.1
    
    # 2. 信息密度（0-0.3）
    # 包含具体步骤、代码示例、错误处理等
    if "步骤" in memory.get("content", "") or "代码" in memory.get("content", ""):
        score += 0.15
    if "错误" in memory.get("content", "") or "解决" in memory.get("content", ""):
        score += 0.15
    
    # 3. 时效性（0-0.2）
    # 越新的记忆分数越高
    days_old = (datetime.now() - memory.get("created_at", datetime.now())).days
    if days_old < 7:
        score += 0.2
    elif days_old < 30:
        score += 0.15
    elif days_old < 90:
        score += 0.1
    
    # 4. 使用频率（0-0.2）
    access_count = memory.get("access_count", 0)
    if access_count > 10:
        score += 0.2
    elif access_count > 5:
        score += 0.15
    elif access_count > 0:
        score += 0.1
    
    return score
```

#### 核心算法

```python
def evolve_memory(new_memory: dict, platform: str) -> dict:
    """
    记忆进化流程
    1. 搜索相关记忆
    2. 评估新记忆质量
    3. 比较并决定是否替换
    4. 保存快照（如果替换）
    """
    # 1. 搜索相关记忆
    related_memories = search_related_memories(new_memory)
    
    # 2. 评估新记忆质量
    new_quality = evaluate_memory_quality(new_memory)
    
    # 3. 比较并决定是否替换
    for old_memory in related_memories:
        old_quality = evaluate_memory_quality(old_memory)
        
        # 如果新记忆更优，替换旧记忆
        if new_quality > old_quality * 1.1:  # 新记忆质量高出10%以上
            # 4. 保存快照
            save_snapshot(old_memory)
            
            # 5. 更新记忆
            new_memory["id"] = old_memory["id"]
            new_memory["version"] = old_memory.get("version", 1) + 1
            new_memory["quality_score"] = new_quality
            update_memory(new_memory)
            
            return new_memory
    
    # 如果没有更优的匹配，创建新记忆
    new_memory["quality_score"] = new_quality
    new_memory["version"] = 1
    create_memory(new_memory)
    
    return new_memory
```
